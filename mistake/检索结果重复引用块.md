# 踩坑记录：检索结果出现重复的引用块

## 问题现象

- 智能问答返回的 `references` 里出现 3 条一模一样的引用（同一个文档、同一个块号、相似度距离完全相同）。
- 知识库页面的"检索测试"同样如此：Top-3 结果是 3 份相同内容的文本块。

## 问题原因

有两个层面：

1. **测试文档太小，分块内容高度重叠**：`labor.txt` 只有 3KB，按"500 字/块、100 字重叠"切出的块内容接近，向量距离几乎一致，检索时同一个块容易被反复命中。
2. **测试阶段重复上传**：开发调试时同一个文件被上传了不止一次，向量库里同一个块存了多份副本，检索自然把它们都召回。

另外去重逻辑最初只加在了问答接口（`routes/chat.ts`），检索测试走的另一个接口（`routes/knowledge.ts` 的 `/search`）没有加，所以页面依旧显示重复。

## 解决方法

### 1. 查询时按"文档名+块号"去重（已做）

在两个接口里，检索后、返回前加去重过滤：

```ts
// 按"文档名+块号"去重，避免内容重叠的分块重复出现在结果里
const seen=new Set<string>();
const deduped=results.filter(chunk=>{
    const key=`${chunk.docName}#${chunk.chunkIndex}`;
    if(seen.has(key))return false;
    seen.add(key);
    return true;
});
```

- 问答接口：`houduan/src/routes/chat.ts` 中 `references=chunks;` 之后。
- 检索接口：`houduan/src/routes/knowledge.ts` 中 `searchChunks(...)` 之后，并把 `res.json` 里的 `data:results` 改为 `data:deduped`。

### 2. 根本清理（待做）

正式入库真实文档前，删除 `houduan/vector_db/` 目录并重新上传文档，让向量库数据重建，清掉历史重复副本。

## 经验总结

- 同一套检索逻辑如果服务多个入口（问答 + 检索测试），改动时要想到所有调用方，只改一处会出现"修了这边那边还错"的错觉。
- 调试阶段反复上传同一文件会污染向量库，测试环境要养成"重来先清库"的习惯。
