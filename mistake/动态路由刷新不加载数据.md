# 踩坑记录：动态路由页面刷新后不加载数据

## 问题现象

- 会话功能里，组件按路由参数加载数据：`/chat/:sessionId` 切换到不同会话时要重新拉消息。
- 写法一：只在 `onMounted` 里读一次 `route.params.sessionId`——**页面内点会话正常，但直接刷新 / F5 就加载了**（onMounted 里明明读了参数，怎么也不行？其实能读到，问题是后续切换不触发）；
- 写法二：用 `watch(() => route.params.sessionId, ...)` 监听——切换会话正常了，但**不渲染时不触发**（不带 immediate 的话首次进入不执行）。

## 问题原因

两个钩子各管一段，单靠谁都不完整：

- `onMounted`：只在组件**首次创建**时执行一次。同组件不同参数间切换（/chat/1 → /chat/2）Vue 复用组件实例，**不会重新 mount**；
- `watch` 不带 `immediate`：只监听**变化**，首次进入时没有"变化"可触发。

## 解决方法

两种等价写法，选一种坚持到底：

```ts
// 写法 A：watch + immediate，一处搞定
watch(() => route.params.sessionId, (v) => load(v), { immediate: true });

// 写法 B：不带 immediate，onMounted 手动补首次（本项目采用）
watch(() => route.params.sessionId, (v) => load(v));
onMounted(() => { load(route.params.sessionId); });
```

两种都别混用——写了 `immediate: true` 又在 onMounted 里加载，会**重复请求两次**。

## 经验总结

- 同组件多参数路由（详情页/编辑页通用组件）的数据加载，本质是"首次 + 参数变化"两个时机，先想清楚再选钩子。
- 重复的请求不只是性能问题：本项目里两次加载会让消息列表闪动，如果在加载里有副作用（上报、清空状态）就是真 bug。
