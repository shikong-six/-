# 流式输出"还是像一大块"——API 按块突发下发，加打字机队列匀速吐字

## 问题

接上一篇《流式一大坨冒出来是首字延迟不是代理缓冲》：加了 status 进度事件后，等待期有反馈了，但答案出来的过程仍然不像"逐字输出"——虽然数据确实是流式到达的，视觉上还是一段一段地蹦，用户反馈"间隔时间太短，容易一下子看成一大块"。

## 原因

计时脚本早已暴露真相：**Moonshot API 的流式是按块下发的，不是按字**。一次 `data` 事件可能携带 8 个 token、同一毫秒到达；生成阶段速度约 27 token/秒（约 50 字/秒）。前端"来多少渲染多少"，等于把 API 的突发节奏原样呈现——一秒内涌入几十个字，肉眼看起来就是"一大块"。

所以问题不在传输层（流是通的），而在**呈现层**：接收节奏（突发）和感知节奏（匀速）不一致。

## 解决方法：打字机队列

核心思路：**解耦"接收"和"渲染"**——token 到了不直接上屏，先排队，用定时器按固定节奏吐给页面。

```ts
let typeQueue = '';           // 待吐出的字
let typeTimer = null;
let typingTarget = null;      // 正在打字的消息

// 接收端：token 入队（喂多快都行）
function feedTypewriter(msg, text) {
  typeQueue += text;
  typingTarget = msg;
  msg.typing = true;
  if (typeTimer) return;
  typeTimer = setInterval(() => {
    typingTarget.content += typeQueue.slice(0, 2);  // 每 30ms 吐 2 字
    typeQueue = typeQueue.slice(2);
    if (!typeQueue) stopTypewriter();
  }, 30);
}

// 流结束/出错时：把队列剩余的字一次性倒完，保证内容完整
function flushTypewriter() {
  if (typingTarget && typeQueue) typingTarget.content += typeQueue;
  stopTypewriter();
}
```

三个必须处理的边界：

1. **流结束时队列往往没排空**（后端 done 了，打字机还欠着字）——done/error 时 `flushTypewriter()` 倒完，且入库用的完整内容要等冲刷后再取
2. **用户抢发新问题**：流已结束但打字机还在吐时，`streaming` 标志已复位，用户可能发新问——`send()` 开头先 `flushTypewriter()` 把上一条倒完，避免两条消息共用一个打字机状态
3. **光标状态**：拆成 `loading`（流未结束）和 `typing`（队列未排空）两个标志，两者任一都显示光标

效果：无论 API 怎么突发，上屏速度恒定在约 60 字/秒，接近真人打字，流式感稳定可感知。

## 一句话总结

流式数据"到了就渲染"会忠实暴露 API 的突发节奏；加个队列 + 定时器把接收和渲染解耦（打字机效果），用恒定节奏上屏，突发在队列里被抹平。注意 done 时冲刷队列、新会话前清空状态两个边界。
