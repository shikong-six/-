# 踩坑记录：停掉后台任务后端口仍被占用（EADDRINUSE）

## 问题现象

- 重启前端 dev server 时报错退出：`Error: listen EADDRINUSE: address already in use :::8080`。
- 明明"旧服务"已经停了——请求它甚至还能正常返回。

## 问题原因

通过 `npm run dev` 起的开发服务是**两层进程**：shell（npm）→ node（webpack serve）。杀掉后台任务时，被杀掉的往往只是最外层的 shell，**node 子进程脱离了管控继续存活**，端口一直被占着。

新进程起来 bind 端口时发现被占，直接 EADDRINUSE 退出。而此时请求 8080 打到的是那个"没人管的孤儿进程"——它还在跑**旧代码**，这也是"改了配置没生效"的经典原因。

## 解决方法

按端口找到真正的占用进程杀掉（Windows 下 Git Bash 没有 netstat，用 PowerShell）：

```bash
# 查占用 8080 的进程 ID
powershell -NoProfile -Command "(Get-NetTCPConnection -LocalPort 8080 -State Listen).OwningProcess"
# 杀掉它
powershell -NoProfile -Command "Stop-Process -Id <PID> -Force"
```

杀完确认端口释放再重启。

## 经验总结

- "任务停了"不等于"进程死了"：重启服务遇到 EADDRINUSE，先怀疑有孤儿进程。
- 排查"改了配置没生效"也是同一招：确认你请求的那个进程确实是新起的（看启动日志/编译时间）。
- 封装一个小函数/脚本"killport 8080"比每次手敲一串 PowerShell 省事。
