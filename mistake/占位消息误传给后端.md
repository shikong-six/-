# 踩坑记录：把占位的空 AI 消息传给了后端

## 问题现象

- 实现流式问答时，前端先 push 一条空的 AI 占位消息（`{role:'assistant', content:''}`），token 到了往里填。
- 写完后自查发现：直接把 `messages.value` 整个传给后端——**占位消息是数组最后一条，后端取 `messages[length-1].content` 当问题，拿到的将是空字符串**。

## 问题原因

非流式实现里，AI 回复是拿到结果后才 push 进数组的，请求时数组最后一条永远是用户问题；流式实现为了边收边渲染提前 push 了 AI 消息，破坏了"最后一条 = 用户问题"这个隐含约定。

这类 bug 很阴：接口不会报错（空字符串也是合法参数），Kimi 会对着空问题自由发挥，现象只是"答非所问"，很难一眼联想到是参数被污染。

## 解决方法

传参时把占位消息排除：

```ts
// 只传占位消息之前的部分（后端取最后一条当问题，不能把空的 AI 占位传过去）
await sendMessageStream(messages.value.slice(0, -1), {...});
```

## 经验总结

- 前后端之间"最后一条消息是用户问题"这类约定，在前端改变消息数组的构造时序后就会悄悄失效。改时序类重构（预渲染、乐观更新）要重新核对每个依赖数组结构的消费方。
- 对入参做校验能挡一大类这种问题：后端对空问题直接 400，比让模型答非所问好排查得多。
