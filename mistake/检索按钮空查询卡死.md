# 踩坑记录：检索测试按钮点了空查询后永久转圈

## 问题现象

- 知识库页面"检索测试"：不输入内容直接点"检索"按钮，按钮进入 loading 状态后**永远转圈**，之后即使输入了内容也点不动了。

## 问题原因

原代码把校验和赋值挤在一行：

```ts
if (!query || searching.value)
return searching.value = true; searched.value = false;
```

`return` 的返回值是后面的赋值表达式，所以当 `!query`（空查询）时，执行的是 `return (searching.value = true)`——**校验失败的分支反而把 loading 标记打开了**，且函数直接返回，永远走不到 `finally` 里的 `searching.value = false`。按钮就此卡死。

## 解决方法

拆成正常的独立语句，校验分支纯返回：

```ts
if (!query || searching.value) return;
searching.value = true;
searched.value = false;
```

## 经验总结

- `return a = b;` 这种写法能编译能跑，但语义极其反直觉，lint 规则（no-return-assign）默认就是禁它的——遇到了直接拆开写。
- 这类 bug 的排查口诀：**loading 卡死 = 有分支打开了标记但跳过了关闭它的 finally**。查所有给标记赋值的路径即可定位。
