# 踩坑记录：AI 生成中切走页面，再回来回答消失

## 问题现象

- AI 咨询页提问后，回答还在流式生成（或刚开始生成）时，点顶栏切到「案例 / 法律条文 / 个人中心」等页面；
- 再点「AI咨询」回来：刚才的对话气泡（用户问题 + 正在生成的回答）不见了，像没问过一样；
- 容易误以为是“安全保护 / 故意清空”，其实不是。

## 和旧坑的区别

另有一篇《切走页面再回来对话现场丢失》讲的是：**入口写死 `/chat`，回来落到空白新对话**（问题其实已入库，侧栏历史里能看到）。

本篇是另一层：**生成尚未结束时组件被卸载，内存现场直接丢光**——库里往往还没有这条问答，侧栏也可能暂时看不到。

## 问题原因

1. **ChatView 默认不缓存**：路由一切走，组件 `unmount`，`messages` / 打字机队列 / `loading` 等全在组件本地 `ref` 里，一起销毁。
2. **流式答案先落内存、后入库**：`POST /api/chat/stream` 要等整段生成完才 `INSERT` 进 `chat_history`；中途离开时 DB 还没有完整记录，回来靠 `loadSession` 拉库也拉不回来。
3. **不是保护措施**：没有“切页就中断并清空”的产品设计；只是「无 keep-alive + 状态只在内存 + 完成后才入库」叠在一起的副作用。
4. **附带坑**：若生成回调里无条件 `router.replace('/chat/:id')`，人在别的页时也可能被强行拽回聊天页——修的时候要避免。

## 解决方法

### 1. 给 ChatView 做 keep-alive（保住内存现场）

`AppLayout.vue` 的 `router-view`：

```vue
<router-view v-slot="{ Component, route: viewRoute }">
  <transition name="page-fade" mode="out-in">
    <keep-alive include="ChatView">
      <component :is="Component" :key="pageKey(viewRoute)" />
    </keep-alive>
  </transition>
</router-view>
```

`ChatView.vue` 必须声明同名，否则 `include` 对不上、缓存不生效：

```ts
defineOptions({ name: 'ChatView' })
```

过渡用的 `pageKey`：`Chat` / `ChatSession` 固定返回 `'chat'`，避免 `/chat` ↔ `/chat/:id` 换 key 导致缓存实例被拆掉。

### 2. 路由 watch 加短路（别缓存了又亲手清空）

`watch(route.params.sessionId)`：

- `loading === true`：只同步会话 ID，**不** `loadSession`、**不**清空 `messages`；
- keep-alive 回来且「同一 `sessionId` + 本地已有消息」：直接 return，不要重拉历史冲掉打字中的气泡；
- 只有真正换会话 / 进空白新对话时才 `loadSession` 或清空。

### 3. onSession 别把人从别的页拽回来

```ts
onSession: (sessionId, historyId) => {
  assistantMessage.id = historyId
  if (sessionId && !currentSessionId.value) {
    currentSessionId.value = sessionId
    sessionStorage.setItem('fazhitong_last_chat', `/chat/${sessionId}`)
    // 人还在聊天页才改 URL
    if (route.path.startsWith('/chat')) {
      router.replace(`/chat/${sessionId}`)
    }
  }
  loadSessions()
}
```

### 4. onActivated 补现场

keep-alive 激活时：续写 `fazhitong_last_chat`、刷新侧栏会话列表、若正在生成或已有消息则 `scrollToBottom`。

### 5. 和旧坑一起用

顶栏「AI咨询」仍读 `fazhitong_last_chat` 恢复路径（见《切走页面再回来对话现场丢失》）。  
**入口能回去 + 组件不被销毁**，生成中切页再回来才完整。

## 经验总结

- 流式聊天、上传进度、长表单编辑这类“进行中状态”，不能假设用户会一直停在当前路由；要么 **keep-alive / 全局 store** 保住现场，要么 **尽早落库 / 可恢复的草稿**。
- “回来为空”先分清两件事：是**导航入口指错页**，还是**组件卸载导致内存态丢失**——修法完全不同。
- keep-alive 之后，路由 `watch` 更容易在激活时误触发“重新拉数据”；要加“同会话 / 生成中”短路，否则等于缓存了又亲手清掉。
