# 踩坑记录：登录鉴权功能的三个关键点（@ 别名 / bcrypt 选型 / JWT 退出）

## 背景

为项目加登录注册 + JWT 鉴权。功能本身顺利，但过程中踩了三个值得记录的坑/决策点。

## 坑 1：`@` 别名 webpack 能跑，vue-tsc 却报"找不到模块"

### 现象

前端代码里用 `@/services/auth`（`@` 指向 src），webpack 构建成功、页面能跑，但 `npm run type-check`（vue-tsc）报：

```
Cannot find module '@/services/auth'
```

### 原因

`@` 别名是在 `webpack.config.js` 的 `resolve.alias` 里配置的，**只对 webpack 生效**；TypeScript 不知道这个映射，类型检查时需要 `tsconfig.json` 里单独配 `paths`。

更隐蔽的是：之前 type-check 就因为这个失败过，但当时用 `tail` 看输出没注意退出码，误以为"零错误通过"。

### 解决

`frontend/tsconfig.json` 加上：

```json
"baseUrl": ".",
"paths": {
    "@/*": ["src/*"]
}
```

### 经验

1. **构建工具的路径别名和 TS 的类型解析是两套体系**，webpack/vite 配了 alias，tsconfig 必须同步配 paths。
2. 验证命令要看**退出码**（`&& echo OK` 或 `$?`），只 `tail` 输出会被"看起来没问题"骗到。

## 决策点 2：用 bcryptjs 而不是 bcrypt

### 原因

`bcrypt` 是 C++ 原生模块，Windows 上安装时需要编译工具链（node-gyp + Visual Studio Build Tools），换台机器 `npm install` 就可能失败。

`bcryptjs` 是纯 JavaScript 实现，**免编译、跨平台稳定**，性能对登录场景（每次登录只哈希/比对一次）完全够用。

### 经验

选依赖时先看它是不是原生模块（`binding.gyp`、prebuild 说明）。教学/演示/小项目优先纯 JS 实现，把环境不确定性降到最低。

## 决策点 3：JWT"退出登录"只是清客户端

### 现象

实现退出功能时发现：没有调用任何后端接口，只是把 localStorage 里的 token 删了。

### 原因（这是 JWT 的设计特性，不是偷懒）

JWT 是**无状态**的：服务端签发后不再保存会话，每次请求只验签。所以：

- 退出 = 删客户端 token，服务端无需任何操作
- 代价：**token 在过期前一直有效**，即使"退出"了，拿到旧 token 依然能调接口
- 补救方案（本项目暂未做，面试可答）：token 有效期设短（如 2 小时）+ 刷新令牌；或维护黑名单表

### 经验

面试常被问"JWT 怎么退出登录/怎么吊销"，标准答案就是上面这套：承认无状态的局限，然后说缓解手段。

## 认证全流程速查（对照代码用）

```
注册/登录 → 后端 bcrypt 校验 → jwt.sign 签发 → 前端存 localStorage
页面请求 → Axios 请求拦截器自动加 Authorization: Bearer <token>
后端 → authMiddleware 验签 → 通过则 req.user 可拿到用户信息 → 401 拦截未登录
退出 → 前端删 localStorage（服务端无状态，无需通知）
路由守卫 → 未登录访问任何页面强制跳 /login
```
