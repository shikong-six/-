# 踩坑记录：切走页面再回来，对话现场丢失

## 问题现象

- AI 咨询页新提问后，点顶栏切到其他页面，再点「AI咨询」回来：刚发的问题"消失"了（其实已入库，侧栏历史里有记录）；
- 在历史会话里继续对话时，切走再点回来：直接变成空白的新对话窗口，原来的会话"退出"了。

## 问题原因

- 顶栏导航菜单是写死的 `router-link` 到 `/chat`（无参新对话页），不管之前在哪个会话；
- ChatView 没有 keep-alive，路由一切走组件就卸载，页面现场（消息列表、当前会话）全靠 URL 参数 `/chat/:sessionId` 恢复；
- 恢复机制依赖 URL 参数，但返回入口永远指向无参的 `/chat`——入口和恢复机制不配套，回来必然落地空白页。

提问本身没问题：提问成功后 `onSession` 回调已 `router.replace('/chat/:id')` 且记录已入库，问题"消失"只是回到空白页造成的观感。

## 解决方法

- ChatView 里 `watch(currentSessionId)` 把最近对话路径实时记到 `sessionStorage`（在会话 → `/chat/:id`；新对话 → `/chat`）；
- AppLayout 顶栏「AI咨询」不再用写死的链接，点击时读 `fazhitong_last_chat` 恢复到刚才的对话现场（没有则进新对话）；
- 退出登录时清掉该值，防止换账号后跳回别人的会话；已在目标路径时不重复 push（避免路由冗余警告）。

## 经验总结

- 带"工作现场"的页面（聊天、编辑器、长表单），离开再回来的导航入口必须能回到现场：要么入口本身带参数，要么像本项目一样用一个轻量的"最近位置"存储恢复。
- 组件状态随路由卸载即丢失，"现场"要么放 URL（可分享、可刷新），要么放存储；导航入口要和恢复机制配套设计，否则机制形同虚设。
- sessionStorage 存"上次位置"时要考虑生命周期：登出/换账号必须清掉，否则会把新会话串到旧位置上。
