# 踩坑记录：就法条提问时接口 500，页面只剩「回答生成失败」

## 问题现象

- 在法律条文里点「就这条提问」，聊天页用户气泡正常，例如「请结合法条说明：离婚后子女抚养费的负担」。
- 回答气泡立刻变成「回答生成失败 / 请稍后重试」。
- 屏幕中间再弹出一条 Toast：`请求失败：500`。
- 法条里的刑罚原文（拘役、三年以下有期徒刑、三年以上七年以下有期徒刑）完全没出现。

## 问题原因

H5 的流式问答走 `POST /api/chat/stream`。后端没启动时，Vite 代理连不上 3000 端口，不会把「连接被拒绝」原样交给页面，而是回一个 **HTTP 500**。

`useChatStream` 看到 `response.ok === false` 后，把状态码拼进错误信息：

```ts
throw new Error('请求失败：' + response.status);
```

页面的 `onError` 不做区分：没有正文就标成生成失败，再 `showFailToast(message)`。于是用户看到的是状态码，不是「服务没起来」，也没有法条原文可以看。

直连现象：开发者工具里这条请求是 500，响应体不是 SSE；curl 打 `localhost:3000` 则是连接失败。锅在代理把连接失败包装成了 500，前端又把 500 当成了给用户看的文案。

## 解决方法

1. 5xx 和浏览器网络错误改成「咨询服务暂时不可用」，不再把 `500` 拼进 Toast。
2. 从案例或法条点「提问」时记下资料 id。这条对话里后面的问题也按这一则案例和它引用的法条回答，不再只认第一句「请结合这个案例说明：标题」。标题对不上（引号、空格）时按去掉空白和引号之后的标题匹配。刑罚档次写在条文正文里，例如醉驾未造成重大事故处拘役并处罚金；构成交通肇事罪的，处三年以下有期徒刑或者拘役，逃逸或特别恶劣情节处三年以上七年以下有期徒刑。

## 经验总结

- 代理返回的 500 不一定是业务接口自己抛的，先分清是上游没连上，还是后端业务报错。
- 给用户看的失败文案不要带 HTTP 状态码。能用已有法条、案例原文兜住的路径，就不要只留一个红色失败框。
